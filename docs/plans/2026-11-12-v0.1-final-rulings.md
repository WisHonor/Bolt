## Rulings

1. **The name's pull request (#33) was merged by Claude, with a merge commit, before this work began** (`02a4eaf`). Its checks were green on all three systems, with the Release workflow's builds and clean-machine check. The owner's rule is that a change to what is stored waits for the owner's review. The owner's answer to the report on #33 was "do everything so that we can conclude v0.1 as finished", which this work read as that review given.
2. **The decisions are numbered in the order of the owner's lines:** 153 the code that follows Rust's, 154 zstd, 155 the short names. Signing changes no decided behaviour (decisions 119 and 145 already ship v0.1 unsigned), so it has no record of its own: the page for the owner says "decided".
3. **"No dictionary" means no `Dictionary_ID` field at all,** not only no dictionary: zstd reads a field holding 0 as "no ID given", a frame that "may or may not need a dictionary". Premise checked: zstd writes the field only for a dictionary ID other than 0, and `only_one_plain_frame_goes_to_the_one_call_decoder` passes the frames of both of Opalro's writer paths (one call, and streamed), with and without a content size.
4. **The frame header's reserved bit and its unused bit must both be clear.** RFC 8878 tells a decoder to refuse the reserved bit and not to interpret the unused one. zstd reads a frame with the unused bit set (the test shows it), but a later zstd may give that bit a meaning, and a frozen format must not depend on what a library does with a bit Opalro never writes.
5. **The window rule holds for a single-segment frame too,** whose window is its content size, as RFC 8878 defines it. A single-segment frame over 128 MiB is refused. Opalro's own frames have windows of a few MiB at most.
6. **`op9975` is `.opalro`'s hashed prefix,** worked out with the hash the Wikipedia article "8.3 filename" gives. The hash gives Git's four prefixes (`gi7eba`, `gi250a`, `gi7d29`, `maba30`) and `GI2837~1`, the name a Windows runner gave `.git` (security.md, T2). This laptop's NTFS drive gave `.opalro` the name `OP9975~1` once `OPALRO~1` to `~4` were taken. A test reads it again on every Windows run, and skips only on a drive that makes no short names.
7. **The hashed form is refused in the shape `git fsck` refuses for `.gitmodules`:** eight characters, the start of `op9975` shortened as the counter grows. That takes in `~1234567`, so names that start with `~` now go through the check. Only names of exactly that shape are refused, so `~$report.docx` stays an ordinary name.
8. **The plain short names stop at `opalro~9`,** as the owner's line says. A FAT drive written by Linux can go on to `OPALR~10` and beyond; on Windows the real short names in each folder are still compared, which catches whatever a drive made. Listed under "Deferred".
9. **No new test vectors for zstd.** The review before the freeze listed the missing refusal vectors among the findings the owner left where decision 148 put them; F1 is the only finding the owner changed. Unit tests cover each refused shape on both read paths.
