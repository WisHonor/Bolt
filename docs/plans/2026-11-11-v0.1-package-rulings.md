# Release v0.1, the package: rulings

The owner asked for v0.1's package to be prepared start to finish while they were away, with every call made by Claude and written down. This file collects those calls. A second session worked on the engine at the same time and has its own rulings file. This file has three parts:
- **Please confirm:** the calls that most change what Bolt does or what the owner signs up for. Each can be reversed. What publishing makes permanent comes first.
- **Every ruling, verbatim:** each ruling and each numbered fact as it was written in the build's ledger, task by task.
- **Deferred:** what this session left for later, and where each item went.

The decisions themselves are records [140](../decisions/140-bolt-is-closed-source.md) to [149](../decisions/149-a-drive-that-cant-name-its-folders-is-told-not-offered-safe-folders.md). Decision 140 (Bolt is closed source) is the owner's. Decisions 141 to 149 are Claude's: each says "Decided by Claude, at the owner's request while the owner was away. The owner can reverse any part." What the owner has to do before publishing is on [the page for the owner](../releases/v0.1.0-before-you-publish.md).

## Please confirm

### First: what publishing makes permanent

1. **The storage format, as the last read stated it** ([decision 148](../decisions/148-what-format-1s-spec-says-before-it-freezes.md)). Format 1 freezes when v0.1 is published: every later Bolt must read what v0.1 wrote. Before the freeze the spec was read once more against the code, and the rule was "say what the code already does; change no byte on disk". So the spec now freezes some things that are looser than what Bolt writes:
   - **zstd.** v0.1 reads one or more zstd frames, passes over skippable frames, and reads the old zstd formats v0.4 to v0.7. It refuses v0.1 to v0.3, dictionaries, a wrong checksum and windows over 2^27 bytes. Bolt itself writes one frame. Tightening the reader to one frame, with no old formats, is possible before the freeze and not after.
   - **TOML.** `bolt.toml` may start with a byte order mark. A file nested deeper than 80 levels, or a key of more than 80 dotted parts, counts as "not TOML".
   - **The conflict record's layout does not freeze.** Only its numbers and its context string do, and what v0.1 does when it meets them. v0.2 defines the layout.
   - **The ignore rules are pinned** to Git as the spec names it (2.52, and 2.56 for `:(optional)`).

   The format review left five more items for the owner ([decision 148](../decisions/148-what-format-1s-spec-says-before-it-freezes.md), last consequence). Each is cheap before the freeze and needs a feature line after it:
   - **Refusal vectors.** The test vectors pin the good bytes of every record, but only the chunk list has examples of bad bytes a reader must refuse. A second reader gets no such examples for listings, saves, the diary and the rest.
   - **Smaller vector gaps.** No vector has a project link in a listing, two extra fields in a save, two move notes, a `redo` diary entry, a rebuilt Git commit, or a pack frame without a content size.
   - **The extra-field limit.** A Git commit whose header is over 64 KiB, or whose message is over 1 MiB, stops a whole import. Raising the limit to 1 MiB would let every commit a save can hold import exactly.
   - **Room to grow in the diary.** Only the save has extra fields. Anything added to a diary entry later needs a new record version. The review's advice: accept that, and say so in the spec.
   - **How `bolt.toml` rules match files.** The spec says patterns use `.boltignore` syntax, but not whether they start at the top folder, what `!` and a trailing `/` do inside one rule, or whether letter case folds. No v0.1 code matches them yet, so v0.2 or v0.3 must define it under the freeze.
2. **The user agreement** ([decision 141](../decisions/141-the-user-agreement.md)). `USER-AGREEMENT.md` is a plain-language draft, marked as a draft for a lawyer, and it ships in every archive. It has four blanks: who grants it (a name or company), the price, who may use Bolt and for what, and the country whose law governs it. A lawyer must read it and the owner fill the blanks before publishing. It promises that Bolt sends nothing, gives no warranty, limits liability to what the person paid, and claims nothing in people's projects.
3. **What Bolt sends: nothing, and each build proves it** ([decision 142](../decisions/142-bolt-sends-nothing-and-each-build-proves-it.md)). Clippy refuses `std::net`'s types, cargo-deny refuses networking crates, and each release program's import list is checked after it is built. Starting another program counts as sending. The check first refuses two tiny probe programs (three on Windows), so a check that sees nothing fails. **Known limit:** a program can load a library by name while it runs, and the check can't see that. A feature that sends anything (syncing, planned for v0.3) needs a new decision and a new agreement first.
4. **The notices, and a question about the C runtime** ([decision 143](../decisions/143-the-notices-cover-what-is-built-in.md)). Each archive holds the crates' notices and the Rust standard library's own notices file (about 1.5 MB more). MPL-2.0 is allowed for one crate only, `option-ext`, and the notices say where its source is (crates.io). **The question for the lawyer:** the Windows program has Microsoft's C runtime built in, and whether the copy on GitHub's runner may be used for a paid product depends on who holds which Visual Studio license.
5. **The addresses** ([decision 144](../decisions/144-where-people-get-bolt-and-report-problems.md)). People download Bolt from the owner's website and report problems, security problems included, to the owner's report address. Both addresses are blanks. Until they are filled, the documents say "the page you downloaded Bolt from". Nothing that ships or goes on the website points into the repository, and a test checks it. The website copies of `json.md`, `storage-format.md` and `benchmarks.md` have their links into the repository turned into plain text, so readers lose them. Write the report address as plain text or an https link: the guide's test refuses a `mailto:` link.
6. **The release workflow** ([decision 145](../decisions/145-one-release-workflow-for-every-version.md)). One workflow serves every version: change the version in `Cargo.toml`, add the release notes, start it by hand from `main`. Each archive holds exactly six files, and a zip of the website copies comes with them. A pull request's builds are kept 3 days. After the attacker's review the workflow also binds each file to the hash its build job printed, pins its container images by digest, rebuilds `SHA256SUMS` from the bound hashes, and refuses the draft unless CI passed on the commit. The owner still compares the downloads with the hashes in the build logs, and the text of `SHA256SUMS` with the `sums` log.
7. **The systems claimed, and the clean machines** ([decision 146](../decisions/146-the-clean-machine-check-and-which-systems-each-build-needs.md)):
   - **Claimed:** Windows 10 or 11, or Windows Server 2016 or later, 64-bit Intel or AMD; Linux with glibc 2.34 or newer; macOS 11 or later on Apple silicon or Intel. The Intel program declares 10.12, but the guide claims only 11.
   - **Tried on every release run:** Windows Server 2025 and 2022, and Windows Server Core in a bare container (no build tools, no Visual C++ runtime, no Git); AlmaLinux 9, Ubuntu 22.04 and Debian 12 in bare containers, and Ubuntu's latest runner; macOS 15 on both kinds of Mac.
   - **GitHub retired its macOS 14 runner on 2026-11-02,** so Apple silicon is tried on macOS 15 only. Nothing older than macOS 15 is tried.
   - **Windows 10 is untried.** No runner offers it. A Windows 10 or 11 desktop without the build tools is worth one run by hand.
   - The macOS jobs cost ten times their minutes once the repository is private.
8. **FAT32 and exFAT drives on Windows can't be used in v0.1** ([decision 149](../decisions/149-a-drive-that-cant-name-its-folders-is-told-not-offered-safe-folders.md)). Most USB sticks and SD cards are formatted that way. Such a drive won't tell Bolt a folder's identity, so Bolt can't tell whose project it is, and `safe-folders` can't vouch for it. Bolt refused there before too, but offered a `safe-folders` line that did nothing. Now it says why and offers no line, and the guide says to work on a copy on the computer's own drive. What Bolt trusts didn't change, so no red-team session was run; the owner may ask for one on `repo.rs`. On Linux both kinds of drive were tried and work. On macOS they are untried.
9. **The follow-ups due before v0.1** ([decision 147](../decisions/147-the-package-sessions-follow-ups-before-v0.1.md)). The license is done (decision 140). The clean Windows is done once the release program passes on Windows Server Core. The walk's row is closed: what is left of it changes nothing. The store's memory of checked copies was moved past v0.1 by decision 109, and its label now says so. `deny.toml` keeps passing over Bolt's own crates, since they are closed and never published.

### Facts checked before the decisions

4. **The notices cover every crate, and zstd's bundled C code, but not Rust's standard library or the Windows C runtime.** Read the `third-party-licenses` artifact of run 42951072197 (cargo-about 0.9.3 output): 42 license blocks; zstd-sys's bundled zstd carries Meta's BSD-3-Clause text; encoding_rs's WHATWG data and the Unicode data have their texts; blake3's C and assembly are the crate's own code under its own licenses. Rust's standard library is in no crate graph, so cargo-about never sees it; the Windows build links Microsoft's C runtime statically (`+crt-static`).
5. **The toolchain ships its own notices for the standard library.** `share/doc/rust/COPYRIGHT-library.html` (1.5 MB) is installed by the `rustc` component (listed in `lib/rustlib/manifest-rustc-x86_64-pc-windows-msvc`), so every toolchain that builds Bolt has it. Copying that file beside the program is the Rust project's own account of what the standard library contains.
6. **The one MPL-2.0 crate is `option-ext` 0.2.0,** reached through `directories` 6.0.0 → `dirs-sys` 0.5.0, used by `config.rs` to find the settings folder (`cargo tree -i option-ext`). No crate where cargo-about chose Apache-2.0 (similar, blake3, constant_time_eq) has a NOTICE file.
7. **An import check can prove "sends nothing".** The release `bolt.exe` in `target/release` (2026-11-09) imports no network library (no WS2_32, WININET, WINHTTP, DNSAPI) and no call that starts a program (no CreateProcess, ShellExecute, WinExec): dumpbin /IMPORTS. No source file of ours or of the fuzz crate uses `std::net`; every `Command::new` in `crates/*/src` sits inside a test module (walk.rs's at line 3351 is in `mod tests` from line 2119).
