# Release v0.1, the package: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Every subagent runs on Opus.

**Goal:** Bolt v0.1's package is ready for the owner to publish: the license in the repository, the user agreement, notices that cover everything built in, a proof that Bolt sends nothing, builds checked on clean machines, documents that a new person can follow word for word and that point nowhere private, what testers are given, and a page that tells the owner what to do. Publishing stays the owner's.

**Architecture:** Almost nothing here is engine code. The work lives in four places: files at the repository's top (`LICENSE`, `USER-AGREEMENT.md`, `README.md`, `SECURITY.md`) and in `docs/` (the guide, the release notes, what testers are given); the release workflow and its scripts (`.github/workflows/release.yml`, `.github/release/*`), which build, check, pack, sum, try on clean machines and draft; the cargo-deny, clippy and cargo-about settings (`deny.toml`, `clippy.toml`, `about.toml`, `about.hbs`); and one test file, `crates/bolt-vcs/tests/guide.rs`, which holds the shipped documents and the manifests to their rules. Each check that can run on this laptop is a script run here first; each that needs another system runs in CI, on a pull request's release run or a hand start of the workflow from this branch.

**Tech Stack:** Rust 1.99.1 (the toolchain in `rust-toolchain.toml`), GitHub Actions on Windows, Linux and macOS runners, Docker on the Linux and Windows runners for the bare containers, `cargo-about` 0.9.3 (pinned, with its checksum), `cargo-deny` through the pinned action, and the systems' own tools for reading a program's imports (`nm` on Linux and macOS, `dumpbin` through `vswhere` on Windows).

**Spec:** decisions [140](../decisions/140-bolt-is-closed-source.md) to [147](../decisions/147-the-package-sessions-follow-ups-before-v0.1.md); [testing.md](../testing.md) §3 (the guide test) and §4 (CI, the `Release` workflow, shipping a fix release); [design.md](../design.md) §6 risks 19 and 20 and §7; [milestones.md](../milestones.md) "Release: v0.1 → The package". Earlier records still in force: [119](../decisions/119-packaging-v0.1.md) (packaging, as 140 to 146 change it), [121](../decisions/121-format-1-freezes-at-v0.1.md) (format 1 freezes when the owner publishes) and [117](../decisions/117-what-json-covers-at-v0.1.md) (`bolt_json` 1 freezes then too).

**Rulings made while building:** kept in a ledger as the build goes, verbatim, and collected in `2026-11-11-v0.1-package-rulings.md` at the end. Every ruling's premise is checked in the code, or on GitHub, before it is made.

**The other session.** An engine session prepares v0.1 at the same time, in `C:\Users\elmas\Desktop\Bolt-speed`, on `v0.1-engine`.
