# Milestone 3 rulings

Rulings made while milestone 3 was built (2026-11-05 to 2026-11-06), copied from the build's progress log before it was deleted. The owner asked for the milestone to be finished without stopping, so every ruling here was made by Claude, and each can be reversed. Decided behaviours that changed have their own decision records; this file is the rest.

## For the owner to confirm

**Decision records made on the owner's behalf** (each says so, and links the record it refines):
- [061](../decisions/061-pack-copy-order-and-lazy-opening.md): which copy of an object is read first, now that packs open only when searched.
- [062](../decisions/062-when-packs-are-merged.md): merge when more than 32 packs are small, judged by their index too.
- [063](../decisions/063-changes-takes-the-save-with-a-flag.md): `bolt changes --save <save>`, so a bare word is always a path.
- [064](../decisions/064-changes-line-limit.md): `changes` shows a file of more than 1,000,000 lines without its lines.
- [065](../decisions/065-matching-work-doesnt-collide.md): unsaved work that already matches the target doesn't stop `goto`.
- [066](../decisions/066-a-pack-bolt-cant-open-for-another-reason.md): only real damage is reported as a damaged pack.
- [067](../decisions/067-the-file-cache-matches-file-identity.md): the file cache matches each file's ID (red-team RT5-1).
- [068](../decisions/068-a-goto-target-that-names-both.md): a `goto` target that is both a line and another save's ID is refused.
- [069](../decisions/069-the-file-cache-matches-the-change-time.md): the file cache matches each file's change time (red-team RT5-5).

**New `unsafe` code** in `crates/bolt-vcs-platform`, walked through line by line in [the walkthrough](2026-11-05-milestone-3-unsafe-walkthrough.md): Task 1's handle-relative file access, and Block 4b (`unsafe impl Plain for FILE_BASIC_INFO {}`, red-team RT5-5). The merge waits for the owner's review (decision 022).

**Behaviour accepted without a new record**, each a known limit written in the docs:
- A case-only folder rename keeps its old spelling on a drive that ignores case; files take the new one (as Git).
- A damaged `.bolt/state/journal` stops changing commands; the hint says deleting it lets commands go on with the files as the switch left them.
- On a folder that keeps case apart inside a drive that ignores case, `discard a.txt` also takes a new `A.txt` (with a safety copy).
- A cloud placeholder fails `status` as it fails `save` (Bolt normally sees OneDrive placeholders as ordinary files).
- A damaged pack stops a save that adds files until it's removed (Bolt can't prove an object absent).
- A no-change save doesn't re-read files the cache vouches for, so it doesn't repair a damaged stored copy.
- `save --line` with nothing changed makes no line (lines start with a save, decisions 021 and 055).
- A line named like another save's ID can't be reached by name until lines can be renamed.
- The file cache still trusts a file deleted and remade that reuses the freed file ID with the same size, time and change time.
- No colour in `bolt changes` on Windows until a console call (new `unsafe`) is reviewed.
- The repository has been private since 2026-11-05: CodeQL, secret scanning and private vulnerability reporting aren't offered on its plan.
