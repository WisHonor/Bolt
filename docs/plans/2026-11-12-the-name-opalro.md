# The name: Opalro

**Goal:** everything that was called Bolt is called Opalro, and whatever a person types says `opalro` ([decision 150](../decisions/150-the-name-is-opalro.md)), and every document gives the owner's addresses ([decision 151](../decisions/151-opalro-com-and-support-at-opalro-com.md)), before format 1 freezes at v0.1.

**Branch:** `opalro`, from `main` at `bf6e651` (the package's merge), in the second working folder.

## Tasks

1. **The decisions and the spec first.** Decisions 150 and 151, a back-link in each record whose names change, `design.md` (the open question "Name" closed), `storage-format.md` and `json.md`.
2. **The mechanical rename.** The crates' folders moved with `git mv`; every living file renamed by one script with ordered rules: archives `opalro-…`, `boltignore`, names inside the code (`BoltName` → `OpalName`), articles ("a Bolt" → "an Opalro"), then `Bolt` → `Opalro`, `BOLT` → `OPAL`, `bolt` → `opal`. Kept: the repository's address and the file names of history records. History records aren't touched.
3. **What a script can't see.** Text about other products (Puppet's Bolt, bolt.new), names spelled in pieces or in hex, a check on a single letter, case variants of the folder's name in test data.
4. **The test vectors,** printed again from the renamed code.
5. **The documents' content:** the guide's part about another program with the command's name, the owner's page, the addresses, the code audit's note.
6. **`opalro` for what a person types** (the owner's correction of decision 150): a second script pass, `opal` → `opalro` for the command, the files, the variables, the settings folder and `opalro_json`, leaving what only the program uses.
7. **A test that no shipped document says Bolt.**
8. **A red-team session** on the folder guard and the renamed format (decision 024).
9. **The final review,** CI on Windows, macOS and Linux, and the pull request, left for the owner: it changes what is stored.

## Rulings

1. **What only the program uses keeps `opal`:** the crates `opal-vcs-*` (and their Rust names, such as `is_opal_alias` and `OpalName`), the context strings `opal-vcs <date> <purpose>` with the same dates, the magic bytes `OPAL…` (eight bytes each, so the short form), and the first line of `.opalro/format`, `opal-repository 1`, which is a magic in words. Everything a person types or reads says `opalro`: the command, `.opalro/`, `opalro.toml`, `.opalroignore`, `OPALRO_…`, the settings folder, `opalro_json`, the archives.
2. **History keeps the old name:** decision records, plans and rulings, red-team reports, the attack code, the clean-room records and the code audit, which gets one note at its top.
3. **Lines inside living documents that record what was asked or planned under the old name keep their words:** the name question's "The question was" in `design.md`, row T12 of `design.md`'s first-review table, and milestone 1's workspace task in `milestones.md`. Their crates.io claims were checked for `bolt`.
4. **The message about another tool's `.opalro` folder names no tool.** bolt.new makes `.bolt` folders; no tool is known to make `.opalro` ones. The rule stays: such a folder is never taken over.
5. **The guide's part about Puppet's `bolt` became one about any other program of the same name.** With the command `opalro`, no program is known to clash with it, so the guide names none; the advice stays, for an older copy left on the PATH: how to tell which comes first, and how to put the new one first.
6. **What the script missed, found by the tests and by reading.** `is_opal_alias` checked for a first letter `b` before anything else, which would have let the folder's short name through. Test data had `.Bolt` and `Bolt.toml` (case variants of the names, turned into "Opalro" by the prose rule), `.b\u{200C}olt` (split by a character macOS ignores), and RT14's folders `b olt` … `b o lt` (named so their short names take `BOLT~1` to `BOLT~4`); each now spells the new name the same way. The test data's example of a hashed short name, `BOC2A3~1`, became `OPC2A3~1`. A test that keeps the repository's address out of shipped documents looked for `wishonor/bolt`, which the script made `wishonor/opal`; it now looks for the owner's account in any form. The release job gathered `bolt-*` archives for the draft, which the script made `opal-*` while the archives are `opalro-*`. The owner's page grepped the build log for `SHA-256 of bolt-`, made `opal-`. Three links into headings that now say Opalro.
7. **The addresses are plain text** in every shipped document, https://opalro.com and support@opalro.com, as decision 144 asked.
8. **The owner corrected decision 150 the same day,** once Ruby's Opal compiler turned out to install an `opal` command: `opalro` for the command and everything else a person types. The record was corrected in place, since it wasn't merged, and its header says so. The second pass kept `opal-…` and snake_case names (`is_opal_alias`, `opal_core`), renamed whole-word `opal` (so variables and test helpers named `opal` became `opalro` with every use), and handled by hand what a word rule can't see: bench's reader of its result files (`-code-opal-`), the folders that take `OPALRO~1` to `OPALRO~4` in RT14's test (`o palro`, `op alro`, `opa lro`, `opal ro`), and the near miss `.opalros`.
9. **`.opalro` and `.opalroignore` share their first six letters,** so on Windows their short names are both `OPALRO~` and a number, in the order they were made. A save never holds `opalro~1` to `opalro~4`, which covers both. The red team was asked to look at it.
10. **A project folder's path on Windows now has room for two fewer characters.** `hide_path` marks `.opalro` hidden through `SetFileAttributesW` with a plain path, a shortcut its comment owns: past 260 characters it fails with an error and touches nothing else. With `.opalro` two letters longer than `.bolt`, a project can't be started or imported in a folder of about 253 characters or more, where 255 worked before. RT8's test made its project folder 250 characters, and on GitHub's Windows machine, whose temp folder Windows spells out three characters longer (`RUNNER~1`), `.opalro` came to 261. The test now makes it 245, which keeps what it tests (paths past 260 below the project), and the known problems tell the limit, which they didn't before.

11. **The red team (RT15) found one Low, fixed:** two import messages printed a joiner inside a `.opalro` spelling as it is ([decision 152](../decisions/152-red-team-rulings-on-the-name.md)). Its two suspicions, about short names a Linux computer can't check on a Windows drive, are neither shown nor new: the choice of refusing more short names is the owner's, before the freeze. The warning kind `nested_opal_folder`, which `--json` gives scripts, became `nested_opalro_folder`: the second pass had kept it, glued to an underscore, and decision 150 says what a person reads says `opalro`.
12. **The final review's fixes.** The first line of `.opalro/format` says `opalro-repository 1`, which reverses ruling 1's part about it: a person can open the file, the program prints the line when it meets a format it doesn't know, and nothing limits its length, as a magic's is limited. The test vectors' key `opal_toml` became `opalro_toml`, next to `opalroignore_block`. Also: the owner's page's PowerShell grep of the build log, which ruling 6 had fixed only for Git Bash; the style test's width, which no longer made the longer command fall at the edge (41 columns now, where 39 made `bolt` fall); RT15-1's proof, which now also checks that the name is shown; an example in `json.md` in the order the program prints it; "every ID changed", which is true of records only, since a file's content ID uses no context string; three back-links whose records' stored names became `opal`; `website.sh`, which takes out links to any repository on the owner's account, so renaming this one can't break a release; the website documents checked for Bolt on every push, not only in a release run; the nightly fuzzing's corpus, kept under a new name since the old inputs begin with the old magic bytes; folder names in the owner's page, the benchmarks and the first-run check; and a claim in the red-team brief, corrected there.

## Deferred

- **More short names refused** (ruling 11, decision 152): `opalro~5` to `opalro~9` and the NTFS hashed form, on every system. Part of format 1's spelling rule, so before publishing or never: the owner's choice, on the page for the owner and in the follow-ups.
- **Hiding `.opalro` through a long path** (ruling 10): give `SetFileAttributesW` the `\\?\` form of the path, or set the attribute through the folder's open handle. It would lift the limit, but changes what the platform crate hands to Windows, which the owner reviews line by line: left for the owner, in the follow-ups.
