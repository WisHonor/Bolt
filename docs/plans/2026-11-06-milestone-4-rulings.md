# Milestone 4 ("Undo everything"): rulings

The owner was away for the whole build, and asked Claude to decide every open question itself and keep going. This file collects every one of those calls so the owner can review them in one place. It has three parts:

1. **Please confirm.** The calls most worth a second look, because they change what a user sees or what is stored, or because they bend a project rule.
2. **Every ruling, verbatim**, in the order it was made, as written in the build's working notes. Each reads *what was decided — why — what it costs if wrong*.
3. **What was deferred.** Each item is either in [the follow-ups](2026-11-01-milestone-1-follow-ups.md) or ruled harmless.

Decisions 070–081 in `docs/decisions/` record the larger calls in full.

## 1. Please confirm

1. **[Decision 081](../decisions/081-what-building-milestone-4-refined.md): accepted decisions 070, 071, 073, 074, 075 and 077 were edited in place during the build.** CLAUDE.md says to supersede instead. Decision 081 lists each edit, its commit and why, and each record now says "Refined by: 081". The edited text matches the code. If you'd rather have the old texts back and new records instead, say so.
2. **A step's two saves both hold a folder the step only wrote inside** (storage-format.md §9, c67083e). The model test found that undo and redo removed a folder the user made, or stopped at it. This sentence makes the code match decision 071's "they agree everywhere the step changed nothing". A step planned from another save (`undo --to --shelve`, `unshelf` onto another save) records that save's version wherever it writes.
3. **`tidy` keeps every diary end inside the undo window** ([decision 079](../decisions/079-red-team-m4-rulings.md), RT6-1). This keeps a rolled-back or cut-off diary alive for the window. It refines decision 077.
4. **The second look before write-out changes a file** ([decisions 079](../decisions/079-red-team-m4-rulings.md) and [080](../decisions/080-red-team-m4-session-2-rulings.md), RT6-2 and RT7-1). A file another program edits during a switch is left as it is and reported. The instant between the look and the change stays open.
5. **Two red-team findings wait for before v0.1**:
   - RT6-3: picking up a lost `head` after a stopped switch;
   - RT7-2: `tidy` refuses to run after the undo window is made longer.

   Nothing is lost in either, and their proof tests stay ignored.
6. **[Decision 078](../decisions/078-a-pack-bolt-cant-open-gets-its-own-warning.md)**: a pack Bolt can't open for a reason other than damage gets its own warning (`pack_unreadable`). It supersedes decision 066 in part.
7. **The placeholder rule is wider.** A regular file holding exactly a link's stored target, with the same content ID and size, is that link's placeholder to every command: save, switch, finishing a stopped switch, and the safety copies.
8. **When stdout can't take a command's output** (the reader has gone, or a write failed), stderr gets the error, then the warnings, then the failed write's own line. A failed write makes the exit code 1 (json.md §5).
9. **`undo --list` leaves the diary's first entry unnumbered.** `undo N` can't reach it, and decision 072 says the list shows it can't be undone.
10. **`save --amend ""` keeps the old message.** The message comes before the paths on the command line, so an empty message is the only way to amend only some paths and keep the message.
11. **Bolt's own files in `.bolt` are tried again on decision 049's schedule** (10 tries, 100 ms apart) when Windows refuses a rename. A failure names the file (`CantWrite`); a cache's failure doesn't fail the command. The two bare "Access is denied" errors seen during the build probably came from elsewhere, and a follow-up watches for them.
12. **A passing error entering a folder while keeping safety copies now fails the command before it changes anything.** It used to skip the copy (final review M1).
13. **The hostile-diary tests compare `.bolt` whole, except `cache/` and `state/lock-info`.** Every changing command rewrites `lock-info` before it knows it will refuse.
14. **Folders past 126 levels deep are opened again one at a time** (quadratic). This was measured and accepted for milestone 4: the deepest legal tree, with a file in every folder, takes about 84 s to save on Windows. It is in the follow-ups for before v0.1.
