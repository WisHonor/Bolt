# v0.1, clean code and the gate: rulings

The engine session that got v0.1's code ready (2026-11-11; plan [2026-11-11-v0.1-engine.md](2026-11-11-v0.1-engine.md)) made these calls at the owner's request, while the owner was away. Decision 128 is the owner's own; 129 to 133 are Claude's, and the owner can reverse any of them with a new record.

## Please confirm

1. **The platform crate keeps code that follows Rust's standard library** (about 300 lines of `crates/bolt-vcs-platform/src/dir/windows.rs`, MIT or Apache-2.0), with Rust's license in the notices ([decision 131](../decisions/131-code-that-follows-another-projects-is-rewritten-clean.md)). So [the code audit](../releases/v0.1.0-code-audit.md) can't say that no code following another project's code remains, and by your rule **no release build is made until you say so.** Keep it (recommended: its license allows it, and a rewrite is new `unsafe` code for you to review line by line), or ask for it to be written again.
2. **`goto` is held to three and a half times Git's time until v0.2** ([decision 132](../decisions/132-gotos-limit-is-three-and-a-half-times-gits-time.md)), not the three first picked ([decision 129](../decisions/129-gotos-limit-until-v0.2-and-the-status-gate-enforced.md)): the first run under 3, on unchanged code, gave 3.01 on a runner whose Git was unusually quick. The ten runs on the finished code gave 1.91 to 2.70 on Linux.
3. **The `status` limit of twice Git's time can fail on a runner whose Git is unusually quick** with Bolt's own time unchanged (2.207 in one run on unchanged code). It is your rule and was not changed; the ten runs on the finished code all passed (1.49 to 1.87).
4. **The status gate (100,000 files under 2 seconds) now fails its nightly job** (decision 129); it was printed only, "until v0.1".
5. **A deep tree is refused at the first listing a walk meets again** ([decision 130](../decisions/130-a-walk-measures-a-listing-it-meets-again-before-walking-it-again.md)), not by measuring the whole save before every walk, which would have cost every `status`. A planted save within the limits still costs what its size costs (`status` 17 s and 1.4 GB on the red team's 8.4-million-path save; [decision 133](../decisions/133-red-team-v0.1-rulings.md)), as decision 109 already moved to before v0.3.
6. **The rewritten readers give the old code's answers where they differ from Git's**, so no project's verdicts change: a `compatObjectFormat` equal to the repository's hash is read (Git crashes on it), a NUL in a config value or subsection is refused, a boolean of exactly -2^31 is read as true (Git for Windows agrees, Linux Git refuses), `core.bare = maybe` is read, a repeated `ext-` key in a Git LFS pointer is refused, `x\gitmod~1` isn't a short name of `.gitmodules`. Each is in the follow-ups.
7. **The public pattern matcher was renamed `glob_match`**: `wildmatch` is the name of Git's own function and file.
8. **Old records stay as written:** accepted decisions, old plans, rulings and red-team reports that say "port" or "copied from Git's tests" weren't edited; the audit points to them.
9. **Two sentences of storage-format.md §12 changed** (the package session does its last read): the ignore rules are read "as `gitignore(5)` describes and `git check-ignore` decides", and `[z-a]` matches `z` alone, as Git and Bolt always did (the old sentence said it matched nothing).
10. **Data from other projects stays:** the presets' rule lists (GitHub's templates, CC0), Unicode's format-character ranges, ten spinner frames, and the 320-byte SHAttered sample used by one test.

## Every ruling, as it was made

- Ruling: goto's limit until v0.2 is 3 times Git's median (decision 129) — 13% over the worst of the ten runs on record (2.651); a log-normal fit puts a false alarm near 1 in 200 runs, and a change bringing back a third of milestone 6's gain fails most runs — if wrong: either a red nightly from a slow runner (then the cause is written down, no loosening without a record) or a 30-40% goto regression slipping through (its ratio is printed every night).
- Ruling: the status gate (100k files under 2 s) fails its nightly job from v0.1 (decision 129) — "v0.1 ships when" must say what the gate checks; it was "printed and read until v0.1" — if wrong: a nightly red on a slow runner (it runs at 0.17-0.20 s, a tenth of the limit).
- Ruling: the deep tree is caught by measuring a listing when a walk meets it a second time, not by measuring the whole save before every walk (decision 130, option B) — option A reads every listing of every save a command touches, including `status` and the small save, the two steps held to twice Git's time; only shared listings make a save bigger by path than what is stored, so B refuses the same planted saves at once at a set lookup per folder — if wrong: a command that never walks the repeated part of a planted save isn't refused for it (it isn't slow either); verify names it.
- Ruling: C-01 (the Windows half of the platform crate's Dir follows Rust std) stays unchanged, under Rust's MIT/Apache license, with Rust's notice shipped — the license allows it in a closed product and every Rust binary owes std's notice anyway; a clean rewrite is ~300 lines of new unsafe in the code that defends against swapped folders, for the owner's line-by-line review, right before v0.1 — if wrong: the audit can't say "no code following another project's code remains", so by the owner's rule the release build waits for the owner's word (and the owner may order a rewrite).
- Ruling: B-01 (the Git LFS pointer reader, a port of Git LFS's MIT decoder) is rewritten clean, not kept with a notice — the owner's release rule asks that no code following another project's code remain, it is safe Rust, and git-lfs 3.7.0 is installed here to compare against — if wrong: an hour's work a notice would have covered.
- Ruling: ignore.rs and git/config.rs are rewritten whole, and the look-alike group of names.rs whole (N-1 with the gray N-2 and N-3) — the flagged parts are most of each unit, and a unit rewritten whole by someone who never saw it is a cleaner record than a patchwork — if wrong: more code to compare and review.
- Ruling: the auditors' gray items judged behaviour-only stay as they are (B-09 split_header, B-10 octal/mode_kind, B-15 loose header, B-16 delta chain and base cache, B-19 pack checks, B-20 craft.rs, C-09 Jujutsu change-id rule, C-10 Windows owner check, C-13 the 8000-byte binary check), with comments naming Git's internals reworded outside the platform crate — each is a documented format, a method, or a fact expressed in Bolt's own way — if wrong: a lawyer asks for more to be rewritten; the audit lists each.
- Ruling: data kept: presets from github/gitignore (CC0), Unicode Cf ranges (facts; Unicode notice ships), spinner frames (de minimis), the SHAttered prefix (test-only research sample; no other real SHA-1 collision exists to use) — none is code; each is named in the audit — if wrong: trivial to replace except the SHAttered prefix.
- Ruling: accepted decision records, old plans, rulings and red-team reports that say "ported" or "copied from Git's tests" are not edited — they are the record of how the old code came about, accepted decisions are never edited, and hiding them would be dishonest; the audit points to them for the lawyer — if wrong: the lawyer may want them edited, which the owner can do.
- Ruling: about.hbs (the notices template, from cargo-about's example, MIT/Apache) is the package session's file — left as a row for it, not changed here.
- Ruling: goto's limit becomes 3.5 (decision 132, supersedes 129's 3), picked before the ten runs from the eleven on record — a run on unchanged code passed 3; a log-normal fit of 11 puts a false alarm at 1 in 35 for 3, 1 in ~500 for 3.5 — if wrong: a regression of up to half of milestone 6's goto gain can pass about half its runs (still printed nightly).
- Ruling: a save past several limits at once may be refused with another limit's sentence than before — only saves the format already forbids are affected, every sentence is one SaveLimits already uses, and no honest save changes — if wrong: a message names a different limit for an invalid save.
- Ruling: decision 130's before/after timings of goto and changes --save belong to Task 14 (one runner, turn by turn, with the rewrites), not Task 2 — if wrong: none; they are measured there.
- Ruling: Task 4 (a verbatim move plus deletion of copied rows) gets no separate task review — its every line is either moved unchanged (and exercised by the full core suite, green) or deleted material the audit listed; the comparers in Tasks 6, 8 and 10 run old against new through the moved code, and the final review sees the diff — if wrong: a mis-moved helper surfaces in a comparer run instead of a review.
