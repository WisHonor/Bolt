# Before you publish v0.1

This page is for you, the owner. It stays in the repository and never goes on the website. It says what to try, what to confirm, what to ask a lawyer and what to do, in that order, before v0.1 goes out. Everything here was written down on 2026-11-11 by the package session. Three parts wait for the second merge: part 2's list, and parts 7 and 10, marked "filled in by whichever session merges second": the package session and the engine session work on separate branches, and only the second one to merge can see the finished draft.

The short version: publishing is the one step that can't be fully taken back. Once a person has saved a project with v0.1, every later Bolt must read it. So try it, read the list in part 2, and only then publish.

## 1. What to try yourself

Half an hour on a project of your own, then ten minutes in a OneDrive folder. Use the archive from the draft, not a build from your own machine: the point is to try what people will get. The draft is made by the first Release run from `main` (part 10, step 3), so this part waits for that run; publish only after it. Follow [the guide](../guide.md) §2 to install it, exactly as a stranger would. If a step is unclear to you, it will be unclear to them: write it down.

**A project of your own (about 30 minutes).** Work on a copy, not the original. In PowerShell:

```text
bolt --version
Copy-Item -Recurse C:\path\to\my-project $HOME\bolt-try
cd $HOME\bolt-try
bolt start
bolt save "First save"
bolt status
```

Then change a few files the way you normally would (edit code, replace an image, delete a file) and go on:

```text
bolt status
bolt changes
bolt save "Second save"
bolt history
bolt goto <the change ID of "First save", from bolt history>
bolt goto main
bolt undo
bolt redo
bolt undo --list
```

(Not the oldest save in the list: `bolt start` made an empty "Start project" save first, and going there empties the folder. Undoable, but alarming.)

Then the corners. You are back on `main` with nothing changed, so each step below first changes a file:

```text
"more" >> notes.txt
bolt shelf "Half-done idea"
bolt shelf --list
bolt unshelf
bolt discard .
bolt undo
bolt save "More notes"
bolt goto <the change ID of "First save">
"other idea" >> notes.txt
bolt save --line try-something "On a new line"
bolt line
bolt goto main
bolt setup
bolt verify
bolt tidy
bolt status --json
```

(`bolt discard .` throws the change away and `bolt undo` brings it back. `--line` works only off a line: on `main` it is refused, guide §8. Change `notes.txt` to any file of yours.)

Also try importing a Git repository you have, on a copy: `cd` into the copy (the folder that holds `.git`) and run `bolt import`, then `bolt history`. If you have one with Git LFS files, try that too.

While you try, look for: a message you don't understand, a `Next:` line that suggests the wrong thing, anything slow, and anything that changed a file you didn't expect. And try what Git users will type: change a file, then `bolt commit -m "x"` (it should save), and `bolt restore .` (it should explain, not run).

**A OneDrive folder (about 10 minutes).** The guide's §2 says Bolt works in OneDrive, and that this was tried on a real OneDrive folder. Try it on yours:

```text
cd $env:OneDrive
mkdir bolt-onedrive-try
cd bolt-onedrive-try
bolt start --preset code
"hello" > notes.txt
bolt save "In OneDrive"
bolt status
```

Then, in File Explorer, right-click a file in that folder and choose "Free up space", so it is kept online only. Run `bolt status` and `bolt save "After free up space"` again. The guide says Bolt shouldn't see the placeholder; if it stops or says something strange, copy the exact text.

When you are done, `Remove-Item -Recurse -Force .bolt` in each try folder, or delete the folders.

### What publishing makes permanent

**The storage format** (what Bolt writes on disk; [decision 121](../decisions/121-format-1-freezes-at-v0.1.md), [decision 148](../decisions/148-what-format-1s-spec-says-before-it-freezes.md)):

1. **The name "Bolt".** It is built into `.bolt/`, `bolt.toml`, `.boltignore` and the first bytes of every pack file (`BOLTPACK`). Renaming after publishing needs a new format. This is your last chance to rename ([design.md](../design.md) open question "Name", and part 9 below).
2. **zstd is read loosely.** zstd is the compression Bolt stores with; a frame is one compressed piece. v0.1 reads several zstd frames, skips skippable frames and reads old zstd formats v0.4 to v0.7. Bolt itself writes one frame. Tightening the reader to one frame is a few lines now, impossible after ([task 12's review](../../.superpowers/sdd/2026-11-11-v0.1-package/task-12-format-review.md), F1; it called this one blocking).
3. **TOML details.** `bolt.toml` may start with a byte order mark; nesting deeper than 80 levels, or a key of more than 80 dotted parts, counts as "not TOML" ([148](../decisions/148-what-format-1s-spec-says-before-it-freezes.md)).
4. **What is left loose on purpose.** The conflict record's layout does not freeze (v0.2 defines it); the ignore rules are pinned to Git 2.52 (2.56 for `:(optional)`) ([148](../decisions/148-what-format-1s-spec-says-before-it-freezes.md)).
5. **Five small format items, cheap now, a feature line after** (a feature line is the note in `.bolt/format` that makes an older Bolt refuse the project; [148](../decisions/148-what-format-1s-spec-says-before-it-freezes.md), last consequence):
   - refusal vectors (test examples of bad bytes): only the chunk list has examples a reader must refuse;
   - smaller vector gaps (a project link in a listing, two extra fields in a save, two move notes, a `redo` diary entry, a rebuilt Git commit, a pack frame without a content size);
   - the extra-field limit: a Git commit with a header over 64 KiB or a message over 1 MiB stops a whole import; raising it to 1 MiB fixes that;
   - room to grow in the diary: anything added to a diary entry later needs a new record version (the review's advice: accept it, and say so in the spec);
   - how `bolt.toml` rules match files (top folder or not, `!`, trailing `/`, letter case) is unsaid; no v0.1 code matches them, so v0.2 or v0.3 must define it under the freeze.
6. **How big files are cut and stored** ([082](../decisions/082-how-big-files-are-cut-into-chunks.md), [083](../decisions/083-a-chunk-list-is-stored-under-its-files-id.md)): chunks of 16 KiB to 256 KiB (about 64 KiB), only files from 1 MiB to 128 GiB cut, the chunk list as a record type of its own (kind 18), `feature chunks` in `.bolt/format`. Decision 121 keeps *where* Bolt cuts out of the freeze; the limits freeze.
7. **No format change from the speed work** ([109](../decisions/109-the-speed-sessions-follow-ups-and-format-1s-three-open-rows.md)): three rows asking for one (a Git tag stored once, a chunk count bounded by file size, a tighter bound on a stored copy's size) were answered no.
8. **A list of 8,388,608 one-byte chunks takes about 82 s to write out an 8 MiB file** (milestone 5's known costs). It is valid format 1, so a planted project can do this forever after the freeze.

**`bolt.toml`'s keys** ([114](../decisions/114-bolt-toml-keys-and-how-bolt-reads-it.md)):

9. The key names are final: `preset`, `chunk-files-over`, `ask-before-saving-over`, `ask-before-saving-files-over`, `[[rule]]`. Sizes are text with a unit. A key Bolt can't use never stops a command: Bolt warns and uses its own value, so a typo shows only as a warning.

**Command names**:

10. No decision freezes them, but once testers learn them and write scripts, a rename means keeping the old name working too. Check the seventeen names in the guide's §4 now. Related calls: Git's words run only in the forms that mean the same, `bolt restore` is always explained and never run, and `bolt stash pop 2` uses Bolt's shelf numbers, not Git's ([116](../decisions/116-gits-words-as-shortcuts.md), [124](../decisions/124-restore-is-explained-and-a-shortcut-takes-nothing-for-what-it-isnt.md)). `bolt` alone prints the overview and exits with 2; 0 may be friendlier (milestone 6, item 22).

**The `--json` formats** ([117](../decisions/117-what-json-covers-at-v0.1.md), [json.md](../json.md)):

11. `bolt_json` 1 freezes: field names, types, meanings, each warning's `kind` and the exit codes. A field can be added later, never renamed or removed. Errors have no machine-readable code in v0.1; scripts go by the exit code. `verify` gained the problem kind `save_too_big` ([126](../decisions/126-verify-also-finds-a-save-that-cant-be-written-out.md)).
12. Change IDs are written in Jujutsu's letters ([122](../decisions/122-change-ids-in-jujutsus-letters.md)). Display only, but every `change_id` a script stores looks like this from now on.

## 3. What publishing freezes, and how to take a release back

**What freezes the moment you press "Publish release":**

- **The storage format, format 1** ([decision 121](../decisions/121-format-1-freezes-at-v0.1.md), refined by [148](../decisions/148-what-format-1s-spec-says-before-it-freezes.md)). Every later Bolt must open any project v0.1 wrote. New things on disk come only as a `feature` line or a new format number, and a project gets one only when its user asks. [storage-format.md](../storage-format.md)'s status line still says "draft"; the "v0.1 published" pull request changes it.
- **`bolt.toml`'s keys** and their values when absent, and how `.boltignore` is read: part of the format (§12).
- **The name** in `.bolt/`, `bolt.toml`, `.boltignore` and `BOLTPACK`.
- **`bolt_json` 1** ([decision 117](../decisions/117-what-json-covers-at-v0.1.md)): field names, types, meanings, warning kinds, exit codes. Message wording is not frozen.
- **The command names,** in practice (item 10).
- **The tag `v0.1.0`,** which publishing creates on the draft's commit.

**What does not freeze:** where Bolt cuts files into chunks, its caches and temporary files, what commands print for people, and speed (decision 121).

**How to take a release back.** You can, partly.

- **On GitHub:** delete the release with `gh release delete v0.1.0 --cleanup-tag` (or on its page, "Delete", then delete the tag under Tags). This removes it for collaborators. Nobody else sees it once the repository is private anyway.
- **On your website:** take the files and the download page down.
- **What you can't take back:** anyone who downloaded keeps their copy, and every project they saved stays format 1. The format promise stands: a later Bolt must still read those projects. Withdrawing a release does not withdraw the format.
- **Never reuse a version number.** Someone may hold the old `v0.1.0`. The way forward is a fix release, `v0.1.1`, with [testing.md](../testing.md) §4's "Shipping a fix release" steps. A fix release never changes what is on disk or what a `--json` field means.

## 4. What a lawyer should read

Before publishing, a lawyer should read these four things. None of this page is legal advice.

## 8. Signing: not in v0.1

**The builds are not signed** ([decision 119](../decisions/119-packaging-v0.1.md), [145](../decisions/145-one-release-workflow-for-every-version.md)). The guide's §2, "Windows and macOS warn about Bolt", tells people what to do.

**What a person sees the first time:**

- **Windows.** If they unpack with "Extract All" and start `bolt.exe` from Explorer, SmartScreen shows "Windows protected your PC"; "More info", then "Run anyway". Started from a terminal, as the guide does, there is usually no warning. Two exceptions can block it from a terminal too: Smart App Control (Windows 11) blocks it with no "Run anyway", and "Choose where to get apps" set to anything but "Anywhere" can block it too.
- **macOS.** If they double-click the `.tar.gz` in Finder (Archive Utility), the program keeps the download mark, and its first run is blocked, even from Terminal. Apple's sample wording is "Apple cannot check … for malicious software", with "Move to Trash" and "Done"; the wording for a command-line tool on macOS 15 or 26 is not confirmed. To allow it: System Settings, Privacy & Security, "Open Anyway", within about an hour, and the login password. Unpacked with `tar` in Terminal, as the guide says, nothing is blocked. Control-click and Open no longer works since macOS Sequoia (15).

**What signing would need** (2026-11-11 prices):

- **Windows.** Either Microsoft's Azure Artifact Signing, $9.99 a month (Basic). **Individuals qualify only in the US or Canada**; organisations also in the EU, the UK and eight more countries ([quickstart](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart)). ## 9. The name

**Puppet Bolt** is a tool for running tasks on servers, still shipped by Perforce (Bolt 5.2.1, 2026-10-05); since 5.0 its downloads need Puppet Core or Enterprise credentials. A free fork, OpenBolt, installs the same `bolt` command. A person with either has two programs named `bolt`, and the first one on their PATH wins.

Where Puppet installs it comes from Puppet's 4.x packaging; 5.x was not checked.

- **Windows:** Puppet puts `C:\Program Files\Puppet Labs\Bolt\bin` in the **user** PATH. Windows searches the system PATH first, then the user PATH, in order. The guide adds the user's own folder with "New", at the end of the user PATH, so **Puppet's usually wins**. The guide says how to move Bolt's folder up.
- **macOS:** Puppet's `/opt/puppetlabs/bin` comes in through `/etc/paths.d`. The guide's line in `~/.zshrc` puts `~/.local/bin` in front, so **Bolt wins**.
- **Linux:** Puppet puts a link at `/usr/local/bin/bolt`. The guide's line in `~/.bashrc` puts `~/.local/bin` first, so **Bolt wins**. The guide warns not to use `/usr/local/bin` there: `mv` would replace Puppet's.

**What they see** when Puppet's comes first (read from Puppet Bolt 4.0's source; 5.x not checked): `bolt --version` prints only a number, such as `5.2.1`. `bolt start` prints `'start' is not a Bolt command. See 'bolt help'.` and exits with 1. The guide's §2 explains the bare number. When Bolt comes first, the person's Puppet commands (`bolt task run …`) get Bolt's "unknown command" and exit 2: their Puppet scripts break until they fix the PATH.

**bolt.new** is StackBlitz's web app for building apps by chatting with AI. No command clashes, but people searching for "Bolt" find it first.

**The registered trademarks:** BOLT, Puppet, Inc., reg. 8196325, for downloadable server and network administration software; BOLT, StackBlitz, Inc., reg. 8191497, class 42, online SDKs. Both registered 2026-03-31 at the USPTO. Puppet's is the risk: it covers downloadable software, close to what Bolt is. Not legal advice; part 4.

**My honest view:** you sell Bolt, so the name carries legal risk as well as confusion. Renaming after publishing needs a new storage format (item 1). If you would rename at all, now is the cheap moment: today it means changing constants.
