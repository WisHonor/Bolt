# Bolt v0.1.0: the code audit

> **Status:** audited on 2026-11-11, before the v0.1 release, at the owner's request ([decision 131](../decisions/131-code-that-follows-another-projects-is-rewritten-clean.md)). What was done about each finding is in the tables, with the commits that did it; the verdict below is the state of the code when this work was merged into `main`.
>
> **The name:** written before Bolt was renamed Opalro ([decision 150](../decisions/150-the-name-is-opalro.md)). Its paths under `crates/bolt-vcs-*` are now under `crates/opal-vcs-*`; everything else it says still holds.

**In plain words.** Bolt will be sold as a closed product: the source stays private, and people download the program under a user agreement. Some of Bolt's code was written by following other projects' code, most of it Git's, and Git's license (GPL version 2) doesn't allow that in a closed program. This page lists everything in the repository that was found to follow another project's code, or to copy another project's tests or data, says what was done about each, and lists what a lawyer should look at.

## The verdict

- **No code that follows Git's code remains,** and no test material copied from Git's tests or Git LFS's. The code that followed Git's (and Git LFS's pointer decoder) was written again under clean-room rules, checked against the old code on millions of inputs, and judged by reviewers with Git's and Git LFS's source open, who found no part that follows it. The old code is deleted.
- **One part follows another project's code, under a license that allows it:** about 300 lines of the platform crate's Windows folder code follow Rust's standard library (MIT or Apache-2.0). It stays unchanged, with Rust's license in the notices (decision 131).
- **So this page does not say that no code following another project's code remains.** By the owner's rule, no release build is made until the owner rules on that part: keep it under Rust's license (recommended), or have it written again, which is new `unsafe` code for the owner to review line by line.
- **Data from other projects that stays:** the presets' rule lists (CC0), Unicode's format-character ranges (facts), ten spinner frames, and a 320-byte test sample of the SHAttered collision. None of it is code; the table below says why each stays.

## How the audit was made

Three auditors, each a fresh Claude agent that changed nothing, read the whole repository on 2026-11-11 (`main` at `c4bd989`) and compared it with the other projects' code: Git at `v2.56.0` (cloned into a temporary folder outside the repository, then deleted), Git LFS's decoder and tests, Rust's standard library 1.99.1, and any other project a comment, table or structure pointed to. Every module, test, fuzz target, test vector, benchmark script, red-team file, document and dependency was read. Each item got one verdict:

- **Follows code:** Bolt's code reproduces another project's code: the same breakdown into functions, the same order of checks where the documentation doesn't dictate it, translated expressions, the same quirks implemented the same way, or a comment saying it was ported.
- **Copied test material:** cases, rows or fixtures taken from another project's tests.
- **Other project's data:** a table, template or sample file taken from another project.
- **Bolt's own:** Bolt implements a documented format or another program's observable behaviour in its own way; what is alike is what the format or the documentation dictates.
- **Library:** another project used through its interface, as a dependency.

### Libraries

Every library built into Bolt is under a license that allows it in a closed product: MIT, Apache-2.0, BSD, ISC, Zlib, CC0, the Unlicense, Unicode-3.0, and one MPL-2.0 library (`option-ext`, through `directories`), used unchanged. None is GPL or LGPL. Their notices must ship with the program; the release's notices file does that, and these points need checking in it (the notices file is the package session's):

- **Rust's standard library**, built into every Rust program, isn't a crate, so the tool that writes the notices never lists it: its license (MIT and Apache-2.0) must be added, and it covers the platform code that follows it too.
- **zstd's C library** inside `zstd-sys`, taken under its BSD option: Meta's BSD notice must be in the notices.
- **`encoding_rs`**: also the BSD notice of its WHATWG data.
- **`unicode-normalization`**: also the Unicode license.
- **`option-ext`** (MPL-2.0): its license, and where its source is (crates.io).
- **`similar`** (Apache-2.0 only): its license text.

## How the rewrite was done

Every rewrite had three roles, each a separate Claude agent:

1. **A preparer** (who could read the old code) moved each unit's old code aside into a folder of its own, left at the old path only a forwarding of its interface, and deleted the copied test material (`56b7b61`). The interface it reported to the rewriters was signatures only.
2. **A rewriter** wrote the unit again from a behaviour brief, the other project's documentation (Git's manual pages and Git LFS's specification), Bolt's own documents, and the programs themselves (`git` 2.50 and `git lfs` 3.7, run on cases it made up). It was told never to open Git's or Git LFS's source, the old code, its history or this audit's working files, and each listed every file it opened, every command it learned from and every page it read (their reports, with those lists, are kept beside this page, in [v0.1.0-clean-room](v0.1.0-clean-room/), with the rules they were given). Four rewriters wrote the units: one for `ignore.rs`, one for `git/config.rs`, one for the four small units, and a fresh one who restructured two parts of `ignore.rs` a reviewer asked for.
3. **A comparer** called the old and the new code side by side on generated and hand-made inputs, a million cases a property in the end, and reported each disagreement to the rewriter only as an input with both answers. The rewriters changed their code until nothing disagreed: refusals, the order of refusals and the wording of every error included. In this way about twenty families of edge cases were brought back to the old answers, among them a `**` before an escaped `/`, NUL bytes, `compatObjectFormat` naming the repository's own hash, and names with both `/` and `\`. After a late speed fix to the matcher, the old matcher was brought back in a throwaway copy and compared again on a million cases a property, with no disagreement.
4. **A reviewer** with the other project's source open (Git at `v2.56.0`, Git LFS at `v3.7.0`) judged the new code part by part. Its first review of `ignore.rs` found two parts "gray": the bracket parser and the trimming of trailing spaces read too much like another implementation. A fresh rewriter restructured both from a description that named no Git code, and the second review found nothing. `git/config.rs` had two gray points (the order of a list of names, and comments naming C library functions), which were changed. The four small units were judged not to follow at first sight. In the end no part of any rewritten unit was judged to follow.

The new code is also checked against the programs in the tests: `git check-ignore`, `git config`, `git check-ref-format`, `git fsck` and `git lfs pointer --check`, each test saying so and passing where the program isn't installed.

## What a lawyer should look at

1. **Each rewritten module and how it was written:** the table above and the section before this one. The evidence that the new code doesn't follow Git's is the reviewers' part-by-part comparison, not the rewriters' word.
2. **The model may know Git's source from its training.** The rewriters were language models that may have seen Git's and Git LFS's source while they were trained. The clean-room rules keep them from opening it; they can't remove what a model may recall. That is why the reviewers' comparison against the source, part by part, matters most, and why two parts it found too close were written again.
3. **The time the repository was public with the old code and no license.** The repository `WisHonor/Bolt` was created on 2026-11-01 and was public when this audit was made (2026-11-11), with no license. Code that followed Git's code entered it from 2026-10-31 (`names.rs`) and 2026-11-02 (the ignore matcher, the config and ref readers, the copied tests), so it was public with that code for about nine days, if the repository was public from the start (the owner knows). In that time GitHub counted 4,180 clones from 639 sources (most or all of them this repository's own CI jobs, which GitHub doesn't tell apart), no forks, no stars, and page views from one visitor.
4. **The old code stays in the repository's history.** History is never rewritten here (no force-push), so every earlier commit still holds the old code and the copied test rows, and the commit messages and old plans say "port" (`2aa2a4d`, "Port Git's ignore matching, without its recursion"). The accepted decision records, old plans, rulings and red-team reports were left as written, as the record of how the old code came about.
5. **Builds of the old code.** No build of Bolt is kept among the workflow artifacts (78 on 2026-11-11: benchmark and gate results, CodeQL reports and the notices file). The release workflow's run of 2026-11-10 (from `1c0b52f`) put its four archives on a draft release, which the package session deletes. GitHub Actions' caches (108, 11.2 GB) hold compiled build folders of many earlier commits, the old code among them; they are read only by this repository's workflows and expire after seven days unused.
6. **The platform crate** keeps about 300 lines that follow Rust's standard library (MIT or Apache-2.0), with Rust's license in the notices (above).
7. **The libraries' notices** (above): Rust's standard library, zstd's C library, `encoding_rs`'s WHATWG data, the Unicode license, `option-ext` (MPL-2.0) and `similar` must be in the notices file that ships with the program.
8. **Where Git's matcher came from.** Git took its pattern matcher and its test table from rsync in 2012 ("the last commit before rsync turned GPL-3"); Git's copy carries Git's GPL-2.0 license. Neither is a source Bolt's code may follow, and neither is used.
9. **What was cloned to make this audit:** Git's source at `v2.56.0`, Git LFS's at `v3.7.0` and a few other projects, into a temporary folder outside the repository, for the auditors and reviewers only; deleted at the end of the work.
