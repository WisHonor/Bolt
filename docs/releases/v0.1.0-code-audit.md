# Bolt v0.1.0: the code audit

> **Status:** audited on 2026-11-11, before the v0.1 release, at the owner's request ([decision 131](../decisions/131-code-that-follows-another-projects-is-rewritten-clean.md)). What was done about each finding is filled in as the work is done; the verdict below is the state of `main` when the work was merged.

**In plain words.** Bolt will be sold as a closed product: the source stays private, and people download the program under a user agreement. Some of Bolt's code was written by following other projects' code, most of it Git's, and Git's license (GPL version 2) doesn't allow that in a closed program. This page lists everything in the repository that was found to follow another project's code, or to copy another project's tests or data, says what was done about each, and lists what a lawyer should look at.

## How the audit was made

Three auditors, each a fresh Claude agent that changed nothing, read the whole repository on 2026-11-11 (`main` at `c4bd989`) and compared it with the other projects' code: Git at `v2.56.0` (cloned into a temporary folder outside the repository, then deleted), Git LFS's decoder and tests, Rust's standard library 1.99.1, and any other project a comment, table or structure pointed to. Every module, test, fuzz target, test vector, benchmark script, red-team file, document and dependency was read. Each item got one verdict:

- **Follows code:** Bolt's code reproduces another project's code: the same breakdown into functions, the same order of checks where the documentation doesn't dictate it, translated expressions, the same quirks implemented the same way, or a comment saying it was ported.
- **Copied test material:** cases, rows or fixtures taken from another project's tests.
- **Other project's data:** a table, template or sample file taken from another project.
- **Bolt's own:** Bolt implements a documented format or another program's observable behaviour in its own way; what is alike is what the format or the documentation dictates.
- **Library:** another project used through its interface, as a dependency.

### Judged Bolt's own, though close to another project

These implement a documented format or another program's behaviour in Bolt's own way. Comments in them that named the other project's source as their model were reworded (outside the platform crate, which stays unchanged).

| Where | Close to | Why it stays |
|---|---|---|
| `git/object.rs`: reading commit, tree and tag objects | Git's `fsck.c`, `commit.c`, `tag.c` | The object layouts and the damage they can have are documented (`git-mktag(1)`, `fsck-msgids`); Bolt reads them in its own way and adds its own rules. |
| `git/object.rs`: a tree entry's mode, cut to 16 bits as Git keeps it | Git's tree code | A behaviour Bolt must match to name damage as Git does, expressed in Bolt's own way. |
| `git/odb.rs`: a loose object's header, and the chain of deltas with its cache of bases | Git's object files and pack reading | The loose format is documented; the chain and cache are a method (libgit2 uses the same one), and Bolt's split, limits and checks are its own. |
| `git/pack.rs`: a pack's and its index's checks, and the delta format | Git's pack code | The pack, index and delta formats are documented (`gitformat-pack(5)`); the order of the checks is the order of the fields. |
| `git/craft.rs` (tests only): writers of packs, indexes and deltas | Git's pack writers | The shortest loops that write the documented encodings. |
| `crates/bolt-vcs-core/src/id.rs`: a save's change ID from a Git commit's ID, in Jujutsu's letters | Jujutsu (Apache-2.0) | An interoperability rule of a few lines, written in Bolt's own way and documented in storage-format.md §5. |
| `crates/bolt-vcs-platform/src/lib.rs`: who owns a folder on Windows | Git for Windows' ownership check | The same rules (decisions 025, 026 and 030), with other system calls in another order and a result of Bolt's own. |
| `crates/bolt-vcs-core/src/changes.rs`: a file is text if its first 8,000 bytes hold no NUL | Git's diff code | One number, chosen so that `bolt changes` says "binary" where Git does. |
| `crates/bolt-vcs-core/src/chunks.rs`: where a big file is cut | FastCDC, as published (Xia and others, 2016) | An algorithm from a paper; Bolt's table comes from BLAKE3 and its masks and vectors are its own. |

### Libraries

Every library built into Bolt is under a license that allows it in a closed product: MIT, Apache-2.0, BSD, ISC, Zlib, CC0, the Unlicense, Unicode-3.0, and one MPL-2.0 library (`option-ext`, through `directories`), used unchanged. None is GPL or LGPL. Their notices must ship with the program; the release's notices file does that, and these points need checking in it (the notices file is the package session's):

- **Rust's standard library**, built into every Rust program, isn't a crate, so the tool that writes the notices never lists it: its license (MIT and Apache-2.0) must be added, and it covers the platform code that follows it too.
- **zstd's C library** inside `zstd-sys`, taken under its BSD option: Meta's BSD notice must be in the notices.
- **`encoding_rs`**: also the BSD notice of its WHATWG data.
- **`unicode-normalization`**: also the Unicode license.
- **`option-ext`** (MPL-2.0): its license, and where its source is (crates.io).
- **`similar`** (Apache-2.0 only): its license text.
