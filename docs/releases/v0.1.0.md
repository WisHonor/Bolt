Bolt v0.1 is the first release of Bolt, a version control system for code and large binary files together, with its own engine and storage format: it is not built on Git.

It is an early release, for one person on one computer. There is no server yet, so no sharing, merging or locking.

## What it does

- **Saves and history:** `start`, `save`, `status`, `changes`, `history`, `show`, `goto`, `discard`.
- **Lines and shelves:** `line` to try ideas on a line of their own; `shelf` and `unshelf` to put changes aside.
- **Undo for everything:** `bolt undo` takes back any command that changed something, and `bolt redo` brings it back.
- **Presets:** `bolt start` asks what kind of project it is (Game, Code or Custom); Game and Code write their rules into `bolt.toml` and `.boltignore`, and `bolt setup` shows them and switches presets.
- **Big files:** cut into chunks, so a change to part of a file stores only the part that changed.
- **Coming from Git:** `bolt import` brings in a Git repository, Git LFS files included.
- **Looking after a project:** `tidy` and `verify`.

What Bolt writes on disk is documented in `docs/storage-format.md` and frozen from this version: every later Bolt reads what v0.1 wrote.

**Speed:** measured against Git and Git LFS on GitHub's Linux and Windows machines, in `docs/benchmarks.md` (§8 and §9), the losses included. On Git's own source, Bolt's first save takes a fifth of Git's time on Linux and a tenth on Windows, and a small save is level with Git on Linux and quicker on Windows. Git is ahead elsewhere: `status` takes 1.6 to 1.8 times Git's time, and going back to another version about twice Git's time on Linux, so Bolt's own bar of staying within twice Git's time isn't met there yet. Saving a 10 GiB file peaks at 44 MB of memory. On a slow disk Git LFS is quicker at the first save of big files that don't compress, and a long history takes more space than Git's (369 MB against 314 MB for Git's own history), since Bolt doesn't store versions as differences yet.

## Download

One archive per system: `bolt-0.1.0-<system>.zip` for Windows, `.tar.gz` for Linux and macOS (Apple silicon and Intel). Each holds the program, `README.md`, the user guide (`docs/guide.md`) and `THIRD-PARTY-LICENSES.html`.

`SHA256SUMS` lists a SHA-256 for each archive. Check a download with `sha256sum -c --ignore-missing SHA256SUMS` on Linux, or `shasum -a 256 -c --ignore-missing SHA256SUMS` on macOS; the guide's "Installing" section has the Windows command. A match says the file is the one this release's workflow uploaded and arrived whole; it doesn't say who made it, since nothing is signed.

## Not signed

The programs aren't signed. Windows SmartScreen may say "Windows protected your PC" (choose "More info", then "Run anyway"), and macOS Gatekeeper refuses a program from an unknown developer the first time (System Settings, Privacy & Security, "Open Anyway"). The guide's "Installing" section has the steps. Signing is planned.

## No license yet

Bolt has no license yet.

## Known limits

No server, no merging, no locking, no repair (`bolt verify` finds damage but can't fix it), and no export to Git yet. The guide's last section, "What v0.1 doesn't do yet", lists them all.

## For scripts

Every command can print `--json`. The formats are documented in `docs/json.md` and frozen from this version (`bolt_json` 1).

These names changed while v0.1 was being made, before the formats were frozen; a script written against a build from before this release needs them:

| Document | Before | Now |
|---|---|---|
| `start` | `line` (always `"main"`) | `position` (`{"line": "main"}`) |
| `discard` | `restored` | `restored_paths` |
| `discard` | `removed` | `removed_paths` |
| `status` | `not_written_here` | `not_written` |
| `status` | `unfinished_switch`: text or `null` | `unfinished_switch`: `true` or `false` |
| warnings (any command that reads) | kind `damaged_pack` | kind `pack_damaged` |
| `history` | `line` (text or `null`) | `position` (`{"line": …}` or `{"save": …}`) |
| `line` | `current` (text or `null`) | `position` (`{"line": …}` or `{"save": …}`) |
| `changes`, each file | `lines` (`"text"`, `"binary"`, …) | `content` |
| `changes`, each file | value `too-big` | `too_big` |
| `changes`, each file | value `too-many-lines` | `too_many_lines` |
| `setup --preset` | `changes` | `files` |
| `setup` | `rules_file` | `has_rules_file` |
| `setup` | `ignore_lines` | `ignore_block_lines` |
| `save` | `result` value `nothing-changed` | `nothing_changed` |
| a change (`status`, `show`, `changes`) | `change` value `kind-changed` | `kind_changed` |
| a change (`status`, `show`, `changes`) | `kind` value `project-link` | `project_link` |
| `goto`, `discard`, `shelf`, `unshelf` | `files_in_use` (always `[]`) | the field is removed; the `files_in_use` warning stays |
| `goto` | none | `recorded` (`true` or `false`) added |
| every error document | `error.message` and `error.hint` as made | escaped as on screen: same names, but a message holding a control character reads differently |
| every save (`change_id`, `change_id_short`) | letters `k` for 0 to `z` for 15 | Jujutsu's letters, `z` for 0 to `k` for 15: the same bytes, written the other way round |
