# Red-team report — milestone 1 (session 1, decision 024, 2026-11-01)

Proof tests: `crates/bolt-vcs/tests/redteam.rs` (16 Linux tests, all fail as claimed — re-verified by the controller in the sandbox; 2 Windows-only tests, confirmed on GitHub's Windows machine on 2026-11-01, on unfixed code: `rt1_windows_…` fails (the junction version of RT-1 deleted the file), `win_junction_…` passes). Scripts: `redteam/attacks/` (rt4-dev-zero-head.sh, crash-sweep.sh, save-probes.sh). Run: `cargo test -p bolt-vcs --test redteam`.

Counts: Critical 3, High 4, Medium 2, Low 2.

## Findings
- **RT-1 Critical (T3 inside .bolt).** `.bolt/tmp` symlinked (zip/tar keep links) → any command (`open` → `clean_tmp`, repo.rs:308) deletes every regular file in the target folder, silently. Test `rt1_symlinked_bolt_tmp_does_not_delete_files_outside_the_project`; Windows junction twin unverified. Fix: refuse a repo whose `.bolt` or fixed subfolders are links/junctions (one place, `symlink_metadata`); `clean_tmp` deletes only `tmp-<16 hex>` names.
- **RT-2 Critical (T3 inside .bolt).** `store/packs` symlink → `save` writes a pack outside; `state/lock` symlink → any command creates the target file (`create(true)` follows links); `.bolt` symlink without `format` → `bolt start` builds a repository at the target. Tests `rt2_*` (3). Fix: same single check; open the lock without following links.
- **RT-5 Critical, conditional (new: TOCTOU).** Needs someone writing in the project folder during a save. Scan uses no-follow metadata, `store_file` uses `File::open` (follows); the changed-during-save check compares the opened file to itself. Secret stolen within 40 saves in 4/4 runs. Test `rt5_save_never_stores_the_target_of_a_file_swapped_for_a_symlink`. Fix: open no-follow (`O_NOFOLLOW` / `FILE_FLAG_OPEN_REPARSE_POINT`), verify via the open handle that it is the same regular file the scan saw.
- **RT-3 High (T11).** FIFO at `state/head`, `store/packs/zz.pack` or `.bolt/config.toml` hangs commands forever (config one hangs `save` when no identity in env). Tests `rt3_*` (3). Fix: regular-file check, open non-blocking/no-follow.
- **RT-4 High (T7/T11).** `state/head` or `config.toml` → `/dev/zero`: unbounded read, 4 GB RSS in 5 s, OOM-killed. Tests `rt4_*` (2). Fix: one capped reader for every `.bolt` file (head: 65 bytes).
- **RT-6 High (T11).** `diff_folders` recursion; no depth limit in code or spec. 100,000-deep save → `bolt show` stack overflow; victim's next `save` commits then aborts. Tests `rt6_*` (2). Fix: spec depth limit (Git: core.maxTreeDepth), iterative walk.
- **RT-10 High (T7).** Tree bomb: 3 listings × 1,000 entries sharing sub-listings = 10^9 files in 3,616 bytes of packs; `bolt show` aborts on allocation failure; future checkout would create 10^9 files. Test `rt10_tree_bomb_does_not_exhaust_memory_in_show`. Fix: spec limit on total entries per save, counted while walking.
- **RT-7 Medium (new, terminal).** `sanitize` escapes only Cc; bidi overrides (U+202E…) and U+2028/2029 pass. Test `rt7_bidi_override_in_a_file_name_is_not_printed_raw`. Fix: also escape bidi controls and line/paragraph separators.
- **RT-9 Medium (new, identity).** `.bolt/config.toml` overrides the user's own identity; planted "Mallory" became author and saver. Test `rt9_project_config_cannot_override_the_users_own_identity`. Fix: owner decision.
- **RT-8 Low.** `bolt start` prints the folder path raw (ESC/BEL reach stdout). Test `rt8_start_does_not_print_escape_sequences_from_the_folder_name`. Fix: sanitize it.
- **RT-11 Low.** Whole finished error messages are sanitized, so multi-line errors show literal `\x0a`; an unreadable folder is reported as a `.boltignore` problem. Proof: save-probes.sh. Fix: sanitize only untrusted pieces; report unreadable folders as unreadable.

## Unproven
- Planted `.bolt` in an ancestor (`C:\.bolt`, `/tmp/.bolt`) captures commands below it, no ownership check (Git CVE-2022-24765); also blocks `bolt start` there. Sandbox has one user.
- Folder swapped for a symlink during the walk; file swapped for a FIFO (hang). Likely from code; not run.
- Junctions inside the project on Windows (`win_junction_in_project_is_not_walked_into`); RT-1/RT-2 via junctions very likely.
- Wide listings (~50 × 1M entries > 4 GB); RT-10 proves the gap more cheaply.
- File-handle exhaustion from 100k packs; likely a clean error.

## Held up (don't repeat)
Crash at every fault point of save (5) and start (6) left the repo consistent; working-folder symlinks stored as links (no race); `.boltignore` can't re-include `.bolt`/`.git`; broken/unreadable `.boltignore` or unreadable folder stops the save; FIFOs/sockets in the working folder skipped; name rules refuse `..`, `/`, NUL, every `.bolt` spelling; pack reader bounds/checksum/overlap checks, 512 MB record cap with `try_reserve`, zstd output cap (no decompression bomb); `--json` escaping; escapes in history/show messages and names; lock serializes concurrent saves; iterative history walk, no cycles; no panics in change-ID code or `resolve`.
