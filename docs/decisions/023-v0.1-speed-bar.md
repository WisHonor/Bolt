# 023 — The speed bar for v0.1

- **Status:** Accepted
- **Date:** 2026-10-31
- **Agenda topic:** 18 (design review)
- **Refined by:** [decision 088](088-benchmarks-and-the-speed-gates.md) (how the gates are measured and the results published)

## Context

The design review asked whether v0.1 must beat Git LFS to ship, or only publish measurements. Principle 5 says correct first, fast second; principle 4 says every claim must be provable.

## Decision

- v0.1 publishes honest benchmark results against Git and Git LFS ([testing.md](../testing.md) §5), but is not required to beat them.
- Two hard gates must pass before v0.1 ships:
  - saving a 10 GB file uses at most about 500 MB of memory;
  - `status` on an unchanged 100,000-file project takes under 2 seconds on an SSD.

## Consequences

- Both gates become automated benchmarks, run in CI or nightly, with the machine recorded.
- Any public speed claim must come from the published results.
